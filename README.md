# ProseLens

**Explainable analysis of writing patterns associated with machine-generated text.**

ProseLens analyses an essay, highlights the passages whose measurable
properties resemble machine-generated prose, and shows the specific
measurements behind every flag.

No language model is asked whether the text is AI-written. No explanation is
generated by one. Every number in the interface is either a measurement or a
term of the classifier's own arithmetic.

---

## The result, both halves of it

| | |
|---|---|
| Fully machine-written essays | **95.1% accuracy, 0.989 AUC** |
| Human essays partly rewritten by AI | **25.5% detected** |

The second number is the realistic case — a student who writes their own essay
and runs it through a chatbot to polish it. It is in the first table of the
README for the same reason it is in the limitations: a tool reporting only the
first number would be misleading about what it can do.

Reproduce both in two minutes with the [demo essays](examples/README.md).

## 1. Problem

Admissions essays are now frequently written, or partly rewritten, by language
models. The tools claiming to detect this mostly return a percentage with no
evidence, no error analysis, and no account of who they get wrong. Those
numbers get used to make accusations about real people.

## 2. Motivation

A detector that cannot show its reasoning cannot be argued with, and one whose
failure modes are undocumented will fail silently on the people least able to
contest it. The goal was an instrument that produces evidence, reports its
accuracy honestly, and states where it breaks.

## 3. Architecture

```
essay text
  ↓ preprocessing        length-preserving normalization (offsets stay valid)
  ↓ segmentation         spaCy → paragraphs → sentences with exact char offsets
  ↓ feature extraction   8 groups, 3 scopes (sentence / contextual / document)
  ↓ sentence model       logistic regression → per-sentence risk + evidence
  ↓ passage aggregation  sliding 4-sentence windows
  ↓ document model       document features + sentence-score distribution shape
  ↓ evidence generation  decomposition of the model's own log-odds
  ↓ FastAPI  →  React + Vite + Tailwind
```

Detail in [docs/architecture.md](docs/architecture.md).

## 4. Detection methodology

**Two logistic regressions, not one.** Many features — burstiness, coefficient
of variation, length variance — are mathematically undefined for a single
sentence. Running one document-trained model over individual sentences produces
numbers, but meaningless ones, and the evidence panel would then be explaining
noise. `FeatureScope` enforces the separation in code.

**The document model does not average sentence scores.** An essay with every
sentence at 0.5 and one with half at 0.1 and half at 0.9 have identical means
and completely different stories — the second is what partial machine editing
looks like. The model receives the distribution's *shape* and learns what to do
with it.

**Risk and confidence are separate outputs.** Confidence is a defined function
of evidence quantity, coverage and consistency — not a second model output — so
it can be explained exactly. High risk with low confidence is a representable
and meaningful state.

[docs/methodology.md](docs/methodology.md).

## 5. Feature engineering

Eight groups, ~60 features, each named, documented and unit-tested.

| Group | Examples |
|---|---|
| Sentence structure | length, character-per-token, length z-score vs document |
| Lexical diversity | TTR, root TTR, **MTLD**, hapax ratio, stopword ratio |
| Repetition | repeated n-grams, vocabulary/bigram/**POS-template** echo |
| Punctuation | comma, semicolon, colon, dash, quote, parenthesis densities |
| Burstiness / rhythm | coefficient of variation, burstiness, successive difference |
| Syntax | POS ratios, dependency depth, clause complexity, branching |
| Predictability | cross-entropy under a trigram model fit on human training text |
| Formulaic language | fronted adverbials, hedging, **nominalization morphology** |

**No phrase blacklist.** Formulaic language is detected morphosyntactically —
nominalization by suffix (`-tion`, `-ment`, `-ness`), fronted adverbials by
part-of-speech and position. A list of phrases someone believes ChatGPT likes
is a hunch, not a measurement. The nominalization feature reaches 0.764
standalone AUC.

**MTLD over raw TTR.** Type-token ratio falls mechanically with length, so a
classifier fed raw TTR learns sentence length in disguise — and the evidence
panel would say "low lexical diversity" when it means "this sentence is long".

## 6. Dataset

| | |
|---|---|
| Sources | DAIGT v2 (Kaggle) + PERSUADE 2.0 for ELL status |
| Working corpus | 7,987 essays after deduplication |
| Machine essays | **17 distinct generators** — GPT-4, ChatGPT, Claude ×2, Llama-2 7B/70B, Mistral ×3, PaLM, Falcon-180B, Cohere |
| Human essays | PERSUADE 2.0 + Kaggle train_essays, US grades 6–12 |
| ELL fairness set | 609 ELL + 609 prompt-matched non-ELL, held-out prompts only |
| Hybrids | 200 essays, Gemini-rewritten, exact span labels |

**Split: prompt-disjoint, frozen and hashed before any model was fit.**

```
split hash  8599bccd1d049678b048f879b0dcdfad96286bde4c3a1411a697675915225622
train       5,659   10 prompts   16 generators
validation  1,365    3 prompts   10 generators
test          963    2 prompts   10 generators
```

A random row-level split lets a model score well by learning topic vocabulary.
Here every test essay is on a topic never seen in training. This reports lower
numbers than a random split would; they are the honest ones.

Near-duplicates are removed with MinHash + LSH before splitting, so no essay
and its near-twin straddle the boundary.

## 7. Training

```bash
python3 scripts/prepare_dataset.py            # corpus, dedup, freeze split
python3 scripts/extract_features.py           # features + reference LM
python3 scripts/recompute_predictability.py   # out-of-fold predictability
python3 scripts/train.py                      # fit both models
python3 scripts/evaluate.py                   # test metrics, ELL, failures
python3 scripts/evaluate_hybrids.py           # span-level detection
```

Artifacts serialize to **JSON, never pickle** — loading a model cannot execute
code. A test asserts the artifact directory contains only `.json`.

## 9. Error analysis

Three confidently wrong predictions, selected programmatically as the
misclassified test essays furthest from the decision boundary, each with its
real log-odds contributions:
[docs/evaluation.md](docs/evaluation.md#three-confidently-wrong-predictions).

The recurring false-positive mode is **human writers who use many commas and
formal register** — in one case comma density alone contributed +3.29 log-odds,
enough to decide the essay by itself.

The most instructive failure is the reverse: a Llama-70B essay scored **0.006,
confidently human**, because the generator was prompted to imitate a student
and produced deliberate misspellings. Every feature said human. That is the
clearest evidence the detector measures **polish, not authorship**.

## 10. Bias considerations

| Group | n | FPR | 95% CI (Wilson) |
|---|---|---|---|
| ELL writers | 609 | 0.0476 | [0.0334, 0.0676] |
| non-ELL writers | 609 | 0.0657 | [0.0486, 0.0882] |

Difference −0.018, **intervals overlap** — no detectable bias against English
language learners in this population, and directionally they are flagged
slightly *less*.

**This should not be over-read.** These are grade 6–12 students, whose ELL
prose is less polished and therefore less machine-like. It says nothing about
an adult international applicant taught formal academic register — who writes
in precisely the style the strongest features associate with machines, and who
is the population most likely to be harmed.
[docs/limitations.md](docs/limitations.md#5-the-esl-result-is-narrower-than-it-looks).

## 11. Limitations

Short text, adversarial rewriting, partial AI editing, domain shift, unseen
generators, the sophistication confound and the untested adult-ESL population
are all in [docs/limitations.md](docs/limitations.md).

The most important: **the detector does not reliably catch essays that are
mostly human with some AI polishing.** 25.5%. That is the realistic case, and
[`examples/hybrid-edited.txt`](examples/) reproduces it on demand.

## 14. API

| Endpoint | Purpose |
|---|---|
| `POST /api/analyze` | Analyze pasted text |
| `POST /api/upload` | Analyze an uploaded `.txt` (size-capped, strict UTF-8) |
| `GET /api/health` | Liveness and model-load status |

The response field is `risk_score` (0–100), **not** a probability. Measured ECE
is 0.0141, but the mid-range bins are thin — the [0.6, 0.7) bin predicts 0.662
against an observed 0.364 on eleven essays. Calling it a probability would
borrow authority the evaluation does not support.
[docs/methodology.md](docs/methodology.md#calibration).

Interactive schema at `/docs` while the server runs.

## 16. Future work

- **Hybrid-aware training.** Hybrids are evaluation-only; training on span
  labels would attack the weakest result directly.
- **A real admissions-essay slice.** The corpus is argumentative student
  writing, which is not the deployment domain.
- **Adult ESL evaluation**, which the current data cannot support.
- Calibration under domain shift.

## 17. AI tools used

Claude Code was used throughout for implementation. Gemini
(`gemini-3.1-flash-lite`) generated the 200 evaluation hybrids and two of the
four demo essays.

Every design decision, metric and limitation here was reviewed and is
defensible. The two leaks found during development — an in-sample language
model, and a length proxy re-entering through the sentence-score summaries —
are written up in
[docs/methodology.md](docs/methodology.md#two-leaks-found-and-fixed) rather
than quietly patched, because how they were caught is the part worth reading.
