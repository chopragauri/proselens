# ProseLens

**Explainable analysis of writing patterns associated with machine-generated text.**

ProseLens analyses an essay, highlights the passages whose measurable
properties resemble machine-generated prose, and shows the specific
measurements behind every flag. It is not a wrapper around a chat model: no
language model is asked whether text is AI-written, and no explanation is
generated by one.

---

## 1. Problem

Admissions essays are now frequently written, or partly rewritten, by language
models. The tools that claim to detect this mostly return a single percentage
with no evidence, no error analysis, and no account of who they get wrong.
Those numbers get used to make accusations about real people.

## 2. Motivation

A detector that cannot show its reasoning cannot be argued with, and a detector
whose failure modes are undocumented will fail silently on the people least
able to contest it. The goal here was an instrument that produces evidence,
reports its accuracy honestly, and states plainly where it breaks.

The headline result is deliberately two-sided:

| | |
|---|---|
| Fully machine-written essays | **95.1% accuracy, 0.989 AUC** |
| Human essays partly rewritten by AI | **25.5% detected** |

The second number is the realistic case. It is in the README for the same
reason it is in the limitations: a tool that reported only the first would be
misleading.

## 3. Architecture

```
essay text
  ↓ preprocessing        length-preserving normalization (offsets stay valid)
  ↓ segmentation         spaCy → paragraphs → sentences with exact char offsets
  ↓ feature extraction   8 groups, 3 scopes (sentence / contextual / document)
  ↓ sentence model       logistic regression → per-sentence risk + evidence
  ↓ passage aggregation  sliding 4-sentence windows
  ↓ document model       document features + sentence-score distribution shape
  ↓ evidence generation  decomposition of the model's own log-odds
  ↓ FastAPI  →  React + Vite + Tailwind
```

Full detail in [docs/architecture.md](docs/architecture.md).

## 4. Detection methodology

Two logistic regressions rather than one. The sentence model consumes only
features that are genuinely properties of a single sentence; the document model
consumes document-scoped features plus summary statistics of the sentence-score
*distribution*.

The document model does not average sentence scores. An essay with every
sentence at 0.5 and one with half its sentences at 0.1 and half at 0.9 have the
same mean and completely different stories — the second is what partial machine
editing looks like. The distribution's shape is preserved so the model can use
it.

Risk and confidence are separate outputs. Confidence is a defined function of
evidence quantity, coverage and consistency — not a second model output — so it
can be explained exactly.

See [docs/methodology.md](docs/methodology.md).

## 5. Feature engineering

Eight groups, ~60 features, every one named, documented and unit-tested:

| Group | Examples |
|---|---|
| Sentence structure | length, character-per-token, length z-score vs document |
| Lexical diversity | TTR, root TTR, **MTLD**, hapax ratio, stopword ratio |
| Repetition | repeated n-grams, vocabulary/bigram/**POS-template** echo |
| Punctuation | comma, semicolon, colon, dash, quote, parenthesis densities |
| Burstiness / rhythm | coefficient of variation, burstiness, successive difference |
| Syntax | POS ratios, dependency depth, clause complexity, branching |
| Predictability | cross-entropy under a trigram model fit on human training text |
| Formulaic language | fronted adverbials, hedging, **nominalization morphology** |

Two choices worth naming:

**No phrase blacklist.** Formulaic language is detected morphosyntactically —
nominalization by suffix (`-tion`, `-ment`, `-ness`), fronted adverbials by
part-of-speech and position. A list of phrases someone believes ChatGPT likes
is a hunch, not a measurement. The nominalization feature alone reaches 0.764
standalone AUC.

**MTLD over raw TTR.** Type-token ratio falls mechanically with length, so a
classifier fed raw TTR learns sentence length in disguise — and the evidence
panel would then say "low lexical diversity" when it means "this sentence is
long".

## 6. Dataset

| | |
|---|---|
| Source | DAIGT v2 (Kaggle) + PERSUADE 2.0 for ELL status |
| Working corpus | 7,987 essays after dedup |
| Machine essays | **17 distinct generators** — GPT-4, ChatGPT, Claude ×2, Llama-2 7B/70B, Mistral ×3, PaLM, Falcon-180B, Cohere |
| Human essays | PERSUADE 2.0 + Kaggle train_essays, grades 6–12 |
| ELL fairness set | 609 ELL + 609 prompt-matched non-ELL, held-out prompts only |
| Hybrids | 200 essays, Gemini-rewritten, exact span labels |

**Split: prompt-disjoint, frozen and hashed before any model was fit.**

```
split hash  8599bccd1d049678b048f879b0dcdfad96286bde4c3a1411a697675915225622
train       5,659   10 prompts   16 generators
validation  1,365    3 prompts   10 generators
test          963    2 prompts   10 generators
```

A random row-level split would let the model score well by learning topic
vocabulary. Every test essay is on a topic the model never trained on. This
reports lower numbers than a random split would; those are the honest ones.

Near-duplicates are removed with MinHash + LSH before splitting, so no essay
and its near-twin straddle the boundary.

## 7. Training

```bash
python3 scripts/prepare_dataset.py      # build corpus, dedup, freeze split
python3 scripts/extract_features.py     # features + reference language model
python3 scripts/recompute_predictability.py   # out-of-fold predictability
python3 scripts/train.py                # fit both models, validation metrics
python3 scripts/evaluate.py             # test metrics, ELL, failure cases
python3 scripts/evaluate_hybrids.py     # span-level detection
```

Model artifacts serialize to **JSON, never pickle** — loading a model cannot
execute code. A test asserts the artifact directory contains only `.json`.

## 9. Error analysis

Three confidently wrong predictions, taken programmatically from real test
output (highest distance from the boundary among misclassified essays), each
with its actual feature contributions. See
[docs/evaluation.md](docs/evaluation.md#three-confidently-wrong-predictions).

The recurring false-positive mode: **human writers who use many commas and
formal register**. In one case `docmean_punct_comma_density` contributed +3.29
log-odds on its own.

## 10. Bias considerations

| Group | n | FPR | 95% CI |
|---|---|---|---|
| ELL writers | 609 | 0.0476 | [0.0334, 0.0676] |
| non-ELL writers | 609 | 0.0657 | [0.0486, 0.0882] |

Difference −0.018, **confidence intervals overlap** — no detectable bias
against English language learners in this population, and directionally ELL
writers are flagged slightly *less*.

**This should not be over-read.** These are grade 6–12 students, where ELL
prose is less polished and therefore less machine-like. It says nothing about
an adult ESL writer producing a carefully polished personal statement — which
is the population the top features suggest is genuinely at risk. See
[docs/limitations.md](docs/limitations.md).

## 11. Limitations

Short text, adversarial rewriting, partial AI editing, domain shift, unseen
generators, the sophistication confound, and the un-tested ESL population are
all documented in [docs/limitations.md](docs/limitations.md).

The single most important one: **the detector does not reliably catch essays
that are mostly human with some AI polishing** — 25.5% detection. That is the
realistic case.

## 12. Setup

Requires Python 3.11+, Node 18+, and ~2 GB disk.

```bash
python3 -m pip install -e ".[dev]"
python3 -m spacy download en_core_web_sm
npm install --prefix frontend
```

Corpora are not committed (size and redistribution terms). Rebuild with:

```bash
kaggle datasets download -d thedrcat/daigt-v2-train-dataset --unzip -p data/raw/daigt_v2
kaggle datasets download -d nbroad/persaude-corpus-2 --unzip -p data/raw/persuade2
```

## 13. Running locally

```bash
python3 -m uvicorn app.main:app --app-dir backend --port 8000
```

```bash
npm run dev --prefix frontend
```

Then open http://localhost:5173. The dev server proxies `/api` to the backend.

## 14. API

| Endpoint | Purpose |
|---|---|
| `POST /api/analyze` | Analyze pasted text |
| `POST /api/upload` | Analyze an uploaded `.txt` |
| `GET /api/health` | Liveness and model-load status |

The response field is `risk_score` (0–100), **not** a probability — see
[docs/methodology.md](docs/methodology.md#calibration). Interactive schema at
`/docs` when the server is running.

## 16. Future work

- Hybrid-aware training. Hybrids are currently evaluation-only; training on
  span labels would target the weakest case directly.
- Calibration under domain shift — the mid-range bins are thin.
- A real admissions-essay evaluation slice. The corpus is argumentative student
  writing, which is not the deployment domain.
- Adult ESL evaluation, which the current data cannot support.

## 17. AI tools used

Claude Code was used throughout for implementation, and Gemini
(`gemini-3.1-flash-lite`) generated the 200 hybrid essays. Every design
decision, metric and limitation in this repository was reviewed and is
defensible by the author. Two leaks found during development — an in-sample
language model and a length proxy re-entering through the sentence-score
summaries — are documented in
[docs/methodology.md](docs/methodology.md#two-leaks-found-and-fixed) rather
than quietly fixed, because how they were caught matters more than the final
number.
